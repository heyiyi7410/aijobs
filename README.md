# 找工作助手 · 投简历

给不会用电脑的人做的投简历工具。跟着 4 步走，全程只需要点按钮，只有姓名和手机号要打字。

**只投央企、国企、外企**（默认），民营私营企业不会出现。

---

## 一、怎么启动（给使用者）

1. 双击文件夹里的 **`启动.bat`**
2. 第一次会自己装环境，等 1–3 分钟，看到"已经打开了"就好了
3. 浏览器会自动打开页面；没打开就手动访问 `http://127.0.0.1:5000`
4. **那个黑色窗口不要关**，关掉服务就停了。用完了再关

> 如果双击没反应：说明电脑没装 Python，让技术人员装一个 Python 3.9 以上（安装时勾上 Add Python to PATH）。

## 二、四步流程

| 步骤 | 做什么 | 说明 |
|------|--------|------|
| 1 填信息 | **有简历就先传上来**（PDF/Word），名字、电话、邮箱、学历、技能自动填好，你核对一下就行 | 没有简历也能手动填，可以点 🎤 用说话代替打字 |
| 2 选单位 | 单位性质（默认央企/国企/外企）、用工方式、想做什么、城市、期望工资 | 选「不限城市」可看全国 |
| 3 挑岗位 | 按适合程度排好序，点圆圈勾选；**也可以直接敲单位名字搜**（见下） | 默认一个都不预勾，投哪个由你自己决定 |
| 4 去投递 | 一家一家**打开对方的招聘页**，你在里面注册登录后投；留了邮箱的岗位可以调起你自己的邮件 App 发 | 投完一个回来点「下一个」，系统会记下投过哪些 |

### 第 1 步的「传简历自动填」

目标用户不常用电脑，让他们把姓名/电话/邮箱/学历/技能手打一遍是很高的门槛；
但大部分人手里其实已经有一份现成的简历。所以第 1 步的入口是「有简历就传上来」。

- 支持 **PDF**、**Word(.docx)**、纯文本(.txt)；老式 `.doc` 和照片版读不了，
  这时给一句人话（「用 Word 另存为 .docx 再传」），而不是抛个看不懂的错
- docx 用标准库拆包（它就是 zip + XML），**不需要第三方库**；PDF 用 `pypdf`（纯 Python）
- 守住两条，改的时候别破坏：
  1. **只填识别得出来的。** 认不到就留空让用户自己补，绝不猜——手机号邮箱填错的后果是
     面试通知发不到人，比让用户多打两个字严重得多。比如城市只在「期望城市：」这类标签
     附近找，因为「北京大学」里也有「北京」；工作年限也不按工作经历的起止年份推算
     （2021-2023 其实是 2 年，按最早那年算会变成 5 年以上）。年限只认写明年数的说法——
     「5年经验」「两年工作经验」「工龄 8 年」「做电工 5 年」「干这行三年」，数字和中文数字都认；
     但「2019 年做电工到 2024 年」「三年制大专」这类日期和学制一律不当年限（`test_50` 盯着）
  2. **区分可信度。** 手机号邮箱有固定格式，认出来就是对的；姓名靠排版猜、会认错，
     标成 low → 界面上那个字段会显示「简历读到，核对一下」
- 解析**默认只做「读」：不落库、不留文件副本**，认得的值回到界面给用户过一眼，
  确认无误后还是走原来的 `/api/profile` 保存。
  唯一例外：用户勾了「留着这份简历，自动投的时候直接用它」才保存原件
  （存到 `data/resumes/`）——因为自动投要上传带照片和排版的真简历，
  不存就只能用字段拼一页纯文本，照片全丢。不勾就什么都不留
- **认哪些字段**（这些是招聘表必问的，缺一项自动投就空一项让人现打）：
  姓名、手机号、邮箱、性别、出生年月、年龄、最高学历、毕业院校、所学专业、
  毕业时间、工作年限、期望城市、会做的事、自我介绍。
  `性别/出生年月/学校/专业/毕业时间` 只认**带标签**的写法（「性别：男」「出生年月：1999.05」），
  不从正文里猜——工作经历里的 `2019.03-2022.11` 绝不会被当成出生年月或毕业时间（`test_55` 盯着）
- 城市表以前端 `frontend/src/options.js` 的 `CITIES` 为准，后端只是兜底；
  两边是否一致有测试盯着（`test_49`）

### 投递是怎么实现的（三条通道）

| 通道 | 什么时候用 | 要不要密码 | 一键? |
|------|-----------|-----------|-------|
| **跳转投递**（默认主路径） | 岗位没有公开邮箱时 | 不要 | 半自动，一家一家打开 |
| **mailto 调起邮件 App** | 岗位留了 `hr_email` | 不要 | 半自动，一封封点发送 |
| **系统代发** | 需要一键批量时 | 要（服务端 SMTP） | ✅ 全自动 |

**为什么主路径是跳转投递**：央企国企的招聘门户（国网招聘平台、国聘网等）和北森、Moka 这类 ATS
**都必须注册登录才能投递**，自动化填表绕不过去、也随时会失效。所以正确做法是把人精准送到对方的
投递页，而不是替他投。这也是合规的做法——不冒充用户投递。

- 岗位数据里 `apply_url` 是投递入口，`hr_email` 有值才会启用邮件通道
- 内置演示岗位全部没有 `hr_email`，所以默认走跳转（央企/国企 → 国聘网）
- 想启用邮件/代发：在你自己的 `jobs.json` 里给岗位填 `hr_email`
- 代发需要 `data/mail.json`（照着 `data/mail.example.json` 填），
  **Reply-To 会自动设成求职者本人邮箱**，HR 点回复直接回到他自己的邮箱
- `dry_run: true` 时邮件不真发，只写到 `data/outbox` 供检查

### 「帮我自动填」（第 4 步里那个按钮）

上一条说「自动化填表绕不过注册登录」——那是说**不能替用户投**。但「把简历在五个网站上
各敲一遍」这件事是可以代劳的，这就是这个按钮干的事：开一个浏览器，替你注册账号、
把资料一项项填进对方的招聘系统，**填完停在「提交」前面让你看一眼**。

| 它替你干 | 必须你亲自干 |
|---------|-------------|
| 打开投递页、认字段、填姓名/手机/邮箱/性别/**出生年月**/**毕业院校**/**所学专业**/学历/城市/薪资/自我评价 | 手机短信验证码 |
| 注册页同上，并把简历作为附件传上去 | 图形验证码、**给这个网站设的密码** |
| 读完给你截图 + 一张「填了什么 / 还差什么」的账目 | 勾《诚信应聘承诺书》、最后点提交 |

上面那三件必须本人做的，不是偷懒留的坑，是**对方网站专门用来分辨「人还是程序」的关卡**。
去绕它等于自报家门，试错几次账号就被锁死——用户在那家单位就再也投不了了。
所以引擎在这三处一律停下来问人，不猜、不试、不绕。

**注册密码**同样必须本人设：不替用户设密码，也不存他的密码——那是他在对方网站的账号，
我们留一份等于把人家的账号抓在手里。

**缺的项有地方补**：点「开始自动填」时，若性别/出生年月/毕业院校/所学专业这些还空着，
会先摆一张表让他补（补完直接存进资料再开跑），而不是等投递结束时甩一张
「要你自己来的（N 项）」——那种清单以前没有输入框，用户看得到却填不了，等于卡死在最后一步。
当然也可以选「先空着，照样投」。

**附件传的是原件**：用户勾了「留着这份简历」时，上传的就是他那份 Word/PDF
（照片、排版、证书扫描件都在）。拿不到原件才退回用字段拼的纯文本兜底。

- 装上才可用：`pip install -r backend/requirements-autofill.txt -i https://pypi.tuna.tsinghua.edu.cn/simple`
  再 `python -m playwright install chromium`（约 150MB，国内建议设 `PLAYWRIGHT_DOWNLOAD_HOST=https://cdn.npmmirror.com/binaries/playwright`）
- 没装也不影响别的功能，只是这个按钮会提示装一下
- 页面里「投到哪里」默认是**本地模拟靶场**（`backend/mock_portal.py`，仿央企招聘系统：
  注册 → 短信码 → 图形码 → 一张几十项的申请表 → 承诺书 → 提交），拿它练手不会真投出去
- 一次只跑一单（浏览器吃内存）。用户中途关掉页面，那一单会自己收工，不会卡住下一单
- 结束时如果拿到回执编号，会自动记进投递记录

### 本地验证自动投（autoapply_demo.py）

想离线把「自动投」全链路跑一遍（不真投出去），用 `autoapply_demo.py`——它现在**数据驱动**，
从真实岗位数据读一批岗位，再按 `apply_url` 自动分流：

```bash
# 1) 默认跑本地仿真靶场，证明管线通（注册→填表→提交→回执）
python autoapply_demo.py

# 2) 给你自己的真实岗位文件（每条含真实 apply_url，见 real_jobs.example.json）
python autoapply_demo.py --input real_jobs.example.json --target auto

# 3) 联网时直接读本地 /api/jobs/search（含国聘/外企等真实源）
python autoapply_demo.py --backend
```

分流规则与真实投递的安全边界（和 `autofill.py` 一致，写死不能改）：
- `/mock/` 开头的 → 仿真流程，沙箱可完整跑通、出回执截图；
- 外链 `http(s)` → 真实流程：到达**具体岗位页**（等 SPA 渲染）→ 识别「申请职位/投递简历」
  等投递入口按钮 → 点它 → **遇到登录墙/短信码/图形码/承诺书/提交按钮一律停下等人**，绝不绕验证码；
- 外链打不开 → 标记「需联网环境」优雅跳过，不卡死。

> 国聘等站点是纯前端 SPA：静态 HTML 只有壳，岗位内容和投递按钮都是客户端渲染的，
> 所以真实流程必须等 JS 渲染后才能扫到「申请职位」按钮（用 `--proxy` 给浏览器配代理）。
> 真实央企国企投递必须登录账号——登录这一步永远交给你本人，绝不代登。

> 跑前建议 `unset http_proxy https_proxy HTTP_PROXY HTTPS_PROXY`，让浏览器只连本地 5000。

### 岗位从哪来（打破信息茧房）

默认**实时抓取国聘网**（iguopin.com，国务院国资委主办的央企国企招聘平台）的真实岗位。
它的搜索接口完全开放——不用登录、不用 cookie、没有签名，返回体还自带单位性质。
实测关键词「电力」100 条里 80 条是国企。

另外接入了**中国公共招聘网**（job.mohrss.gov.cn，人社部官方聚合站）作为第二国企源，
专门补国聘网覆盖不到的地方国资委下属企业。它的列表接口也完全开放（明文 HTTP、无需登录），
但服务端只能按顶层大类筛、没有公司名/国企检索字段，所以拿回来后用公司名关键词二次识别
央企/国企，**命中不了的民企一律丢弃**——宁可漏掉也不把民企谎标成国企。

再接入了**地方国资委/人社局招聘公告**作为第三国企源（`gov_soe`，配置在 `data/gov_soe_sources.json`），
专门补省属/市属国企。各省国资委官网的「国企招聘」专栏是**官方公告、100% 地方国企、零民企污染**，
但岗位是「一篇篇招聘公告 HTML」，所以走「列表页抽公告链接 → 逐篇抓正文 → 解析公司/日期/性质」路线，
单位性质默认判「国企」、公司名命中央企名录则升级「央企」。新地区只需往 JSON 里加一行即可，
无需改代码。已接入**广东**（省国资委·国企招聘专栏）+ **湖北**（华图·国企招聘频道聚合，
因湖北省国资委官网有 WAF 拦截，改用聚合站，仍按公司名限定为国企）。多个源**并行抓取**，
任一源慢或挂都不影响其它源出结果。

### 按单位名搜索（第 3 步顶部搜索框）

很多人是奔着某一家单位去的（「我就想进武钢」「我们那儿邮政在招人」），
让他能直接敲单位名字搜，而不是只能在一堆通用岗位里翻。接口 `POST /api/jobs/company`。

搜法（`app.py` 的 `api_company_search`）：
1. 单位名当关键词抓一轮；
2. 命中太少 → 补一轮不限关键词的宽搜；
3. 还太少 → 放宽到全国（认准一家单位时城市常常可以商量）。
每轮结果都按单位名过滤，评分排序跟普通匹配一致。

单位名匹配有两个层次（`_company_hit` / `_company_loose`）：
- **严格**：归一化（去括号内容、去「有限公司/集团」等后缀）后互相包含——「邮政」↔「中国邮政集团有限公司河北省分公司」；
- **简称兜底**：中国人几乎都打简称，而简称往往**不是**全名的子串（「中建三局」不在「中国建筑第三工程局」里），
  所以严格命中不足 3 条时启用字序子序列匹配——「中建三局」「武钢」「中铁」都能搜到。

两个容易踩的点（都已修）：
- 放宽到全国拿回来的岗位必须标 `nearby`（外地），否则求职者会以为都在自己城市；
- 搜完本市 0 条、外地有货时，前端自动切到「连外地一起看」并明确写出「这家单位在武汉暂时没有岗位，下面是外地的」，
  避免用户对着一堆外省岗发懵。

**投递深链（apply_url）**：每条岗位的 `apply_url` 必须指向「这条岗位自己的页」，
而不是门户首页——否则自动投只能打开首页、找不到投递入口。
- `guopin`/`mohrss`：接口自带岗位 id，直接拼详情页深链（`/job/detail?id=<id>`）；
- `gov_soe`：公告原文页就是这条岗位的具体页，直接作 `apply_url`；同时还会从公告正文里
  **挖真正的报名入口**——正文里出现招聘/报名系统外链（如 `zp.hbjttz.com`、`whzsrc.com/...Detail/...`）
  就优先用它，挖到报名邮箱就填进 `hr_email`（邮件投递通道随之启用）。
  注意两个坑（都已修）：① 聚合站页面上自己的反馈邮箱（如 `fankui@huatu.com`）会被误当
  HR 邮箱——已按"排除来源站自己域名"过滤；② Python 的 `\w` 会匹配中文，宽泛邮箱正则会把
  「…发送至邮箱xxx@163.com」整句吞成邮箱——已限定 ASCII 字符集。

详细的源评估、架构和扩展方式见 **[docs/破茧方案.md](docs/破茧方案.md)**。

渠道优先级：

| 渠道 | 说明 |
|------|------|
| `guopin` | 国聘网实时接口，央企/国企主力源（密度高、字段全） |
| `mohrss` | 中国公共招聘网，第二国企源（补地方国企长尾，按 `textfield` 全文检索 + 公司名识别） |
| `gov_soe` | 地方国资委/人社局招聘公告，第三国企源（100% 地方国企、零民企污染，配置驱动多地区） |
| `foreign` | 外企官网直招（亚马逊中国等） |
| `json` | 读 `data/jobs.json`，自家岗位数据 |
| `http` | 读 `data/collector.json` 里配的内部接口 |
| `sample` | 内置演示库，**仅当上面全部抓不到时才启用**，并在界面上明确标注 |

抓不到时不会报错也不会白屏：单个源挂了自动跳过，城市里机会太少会自动放宽到全国并标「外地」。

### 给不会用的人准备的细节

- **特大字**：右上角 `A+` 一键放大
- **读给我听**：右上角 🔊 会把当前步骤念出来
- **说话输入**：点 🎤 直接说，不用打字（Chrome / Edge 浏览器支持）
- **劳务派遣会标黄提醒**：很多央企国企基层岗是派遣工，不是直接跟单位签合同，界面上会明确标出来
- **央企 / 国企分别标注**：央企按国资委 ~98 家集团名录识别（子公司名带集团核心名即判为央企），不会把地方国企误标成央企
- **招聘人数与校招/社招**：岗位卡会显示「校园招聘/社会招聘 · 招 N 人」（未公开人数则不显示）
- 所有按钮都做得很大，一次只让你做一件事

## 四、AI 匹配怎么算的

本地规则打分，不调任何外部 API，断网可用。权重：

| 维度 | 权重 |
|------|------|
| 技能/标签命中 | 35% |
| 求职意向命中 | 22% |
| 单位性质（央企/国企/外企） | 15% |
| 城市 | 13% |
| 薪资 | 8% |
| 经验/学历 | 7% |

- 用户选「只要直签」而岗位是「劳务派遣」时，**额外扣 8 分**并置顶提醒
- 输出 0–100 分 + 人话理由（"你会的电工证正好是这个岗位要的"）
- 想换真的大模型：把 `ai_matcher.py` 里的 `score_job` 换成一次 HTTP 调用即可

## 七、要不要配后端和网站？

**取决于"不会用的人"在哪里用这台程序。** 三种情况：

| 场景 | 要不要配置 | 具体做法 |
|------|-----------|---------|
| **A. 一台电脑上给人用**（门店/居委会/你自己电脑） | **完全不用配** | 双击 `启动.bat` 就行。后端 Flask 自带服务、前端已打包、数据存本地 SQLite 文件，一个进程全包了 |
| **B. 同一个 WiFi 下多人用**（几台电脑/手机） | 加一个环境变量 | 设 `HOST=0.0.0.0` 再启动，别人用你这台电脑的局域网 IP 访问。可能需要放行防火墙端口 |
| **C. 人在外面、随时打开就用** | **需要服务器 + 域名 + HTTPS** | 见下面部署步骤 |

> 前端调后端用的是**相对路径 `/api`**，所以换域名、换 IP 都**不用改任何前端代码**，也不用改 API_HOST 之类的配置。

### C 场景的部署步骤（Ubuntu + nginx 为例）

前端已经在本地 `npm run build` 打包好了，服务器上**不需要装 Node**。

```bash
# 1) 上传整个 webapp 目录到服务器（比如 /opt/resume-webapp）

# 2) 装依赖
cd /opt/resume-webapp
python3 -m venv .venv && .venv/bin/pip install -r backend/requirements.txt -r requirements-deploy.txt

# 3) 用 gunicorn + eventlet 启动（WebSocket 必须走 eventlet/gevent）
HOST=0.0.0.0 PORT=5000 \
  .venv/bin/gunicorn -k eventlet -w 1 --chdir backend app:app
```

nginx 反代（**`Upgrade` 那两行不能少，否则投递进度条不动**）：

```nginx
server {
    listen 80;
    server_name 你的域名;

    location / {
        proxy_pass         http://127.0.0.1:5000;
        proxy_http_version 1.1;
        proxy_set_header   Upgrade $http_upgrade;      # WebSocket 必需
        proxy_set_header   Connection "upgrade";       # WebSocket 必需
        proxy_set_header   Host $host;
        proxy_set_header   X-Real-IP $remote_addr;
        client_max_body_size 10m;
    }
}
```

```bash
# 4) 签 HTTPS（让用户地址栏是锁，填手机号也放心）
certbot --nginx -d 你的域名
```

建议再配个 systemd 服务让它开机自启、崩了自动拉起。

### 一键部署脚本（连 nginx 都不用装）

纯 IP + 端口访问时，gunicorn 直接监听就行，**不需要 nginx**：

```bash
# 1) 把 webapp 整个目录传到服务器 /opt/resume-webapp
# 2) 跑脚本
sudo bash /opt/resume-webapp/deploy/setup.sh          # 默认 8000 端口
# 或者用 80 端口（境外服务器免备案，手机上不用输端口）
PORT=80 sudo bash /opt/resume-webapp/deploy/setup.sh
```

脚本会自动：装 Python 环境 → 建虚拟环境 → 装依赖 → 配 systemd 开机自启、崩溃自动拉起 → 放行端口。

### 买什么样的服务器

这个应用非常轻，不用买贵的：

| 项目 | 要求 | 说明 |
|------|------|------|
| CPU / 内存 | **1 核 1G 够用**，建议 1 核 2G | 匹配是纯 Python 计算，没有模型、不吃显卡 |
| 系统 | Ubuntu 22.04 | 部署脚本按 Debian 系写的 |
| 带宽 | 1–3 Mbps | 整个页面不到 200 KB |
| 机房 | **境外（东京/新加坡/中国香港）** | 免备案，80 端口直接可用；国内服务器 80/443 必须备案才能开 |
| 参考价格 | 月付 20–40 元 | |

### ⚠ 纯 IP + 端口的三个坑（决定前先看）

| 问题 | 后果 |
|------|------|
| **微信里可能打不开** | 微信内置浏览器对非 80/443 端口、纯 IP 地址支持很差，经常白屏或被拦截。而你要服务的人基本都是「微信收到链接点一下」 |
| **浏览器提示"不安全"** | 第 1 步要填手机号，地址栏挂"不安全"会劝退人 |
| **IP 签不了 HTTPS** | Let's Encrypt 只给域名签证书，纯 IP 无解 |

**建议**：境外服务器 + 一个几块钱一年的域名（`.top` 首年经常不到 10 元），用 80 端口，比纯 IP 好用得多，还能随时加 HTTPS。

确定要纯 IP 也行，但**上线前先把链接发到微信里实测一遍**再推广。

- **进程不能停**：本地那个黑窗口关掉服务就停；服务器上要用 systemd / supervisor 守护
- **SQLite 够不够**：同时几十人用完全没问题（并发写入会有短暂排队）；真到几百人再换 MySQL
- **数据在哪**：`webapp/data/app.db`，备份只要拷这一个文件
- **换岗位数据**：改 `webapp/data/jobs.json` 后**不用重启**，下次搜索自动生效（HTTP 接口源同理）
